# REVIEW.md

Defects found in the starter `app/main.py` (helpers and endpoints). Line numbers
refer to the original starter file.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (L33-37) | Builds the shift start by `punch_in.replace(hour, minute)`, i.e. on the punch-in's **own date and UTC offset**. The punch is a UTC datetime, so "09:30" is applied in UTC, not IST — every late calculation is off by 5:30. It also ignores the attendance date (overnight). | `POST /punch-in` for EMP0003 at `2026-07-06T04:35:00Z` (10:05 IST) returns `late_minutes` computed against 09:30 **UTC**, not 35. | Build the shift instant from the attendance `date` string in IST (`_shift_instant`) and subtract. |
| 2 | `compute_late_minutes` (L37) | Grace logic is `minutes > 10` on **integer-truncated** minutes. R2 says *strictly more than 10:00* and the floor is counted **from shift start**. `09:40:40` (10 min 40 s) truncates to 10, `10 > 10` is false → 0, but it should be late. | Punch at `09:40:40` IST on a 09:30 shift → expected `late_minutes`≈10, got 0. | Compare elapsed **seconds** to `GRACE_SECONDS` (600), then `floor(seconds/60)`. |
| 3 | `compute_work_hours` (L41) | Uses Python `round(x, 2)` — **banker's rounding**. R4 requires **half-up**. | `round(2.345, 2)` → `2.34` in Python; many work-hours land on a 5 and round the wrong way. | `Decimal(seconds)/Decimal(3600)` quantized `ROUND_HALF_UP`. |
| 4 | `compute_overtime` (L44-47) | Three bugs: (a) builds shift end on the attendance date even for an **overnight** shift (should be next day); (b) compares an IST-aware `end` with a **naive** `punch_out` → `TypeError`/garbage; (c) `max(0, …)` returns overtime even when **< 30 min**, ignoring the R3 threshold; (d) `int()` truncates toward zero instead of floor. | Overnight EMP0005 punch-out → exception or wrong minutes; a 5-minute overrun returns 5 instead of 0. | `_shift_instant(date, shift_end, +1 if overnight)`, aware arithmetic, floor, and `>= 30` gate. |
| 5 | `create_employee` (L78-85) | **Check-then-insert** (`find_one` then `insert_one`) with **no unique index** → two concurrent identical creates can both pass the check and both insert. | Fire two `POST /employees` with the same `emp_code` concurrently → two 201s, duplicate rows. | Unique index on `emp_code` + insert; catch `DuplicateKeyError` → 409. |
| 6 | `create_employee` (L82) | `created_at = datetime.now()` — **naive local** server time, not UTC; and it is returned as a datetime, not epoch ms. No `shift_start != shift_end` check, no field validation (pattern/length/email). | `created_at` in the response is a string/!ms and off by the server's offset; `emp_code` `"XYZ"` is accepted. | `now_dt()` (aware UTC, whole seconds) + `dt_to_ms`; pydantic constraints + `model_validator` for shift inequality. |
| 7 | `create_employee` (L84-85) | Returns the raw inserted `doc` after `pop("_id")`, so `created_at` is a datetime and field order/shape isn't the contract shape. | Response fails schema: `created_at` not an integer. | Serialize through `employee_out` (epoch ms). |
| 8 | `list_employees` (L93) | `skip = page * page_size` — **off-by-one**; `page=1` skips the first page entirely. | `GET /employees?page=1` returns rows 21-40, not 1-20. | `skip = (page-1) * page_size`. |
| 9 | `list_employees` (L94) | `total = count_documents({})` — **ignores the department filter**; `total` is always the whole collection. | `GET /employees?department=Sales` → `total` is everyone. | `count_documents(q)`. |
| 10 | `list_employees` (L89,95) | No `page`/`page_size` bounds (R10: min 1, max 100) and **no sort** (contract: `emp_code` asc). | `page_size=100000` is honored; order is undefined. | `Query(ge=1, le=100)` / `Query(ge=1)` → 422; `.sort("emp_code", 1)`. |
| 11 | `punch_in` (L101-102) | `emp` is fetched but **never checked**; an unknown employee hits `emp["shift_start"]` → `KeyError`/500 instead of **404**. | `POST /punch-in` for a missing `emp_code` → 500. | `if not emp: 404`. |
| 12 | `punch_in` (L102-103) | `datetime.fromtimestamp(ms/1000)` → **naive local** time; `ts.date()` → the **server-local** calendar date, not the IST attendance date (R1), and no overnight handling, no whole-second truncation. | A punch near midnight is filed under the wrong `date`; overnight shifts always wrong. | `ms_to_dt` (UTC, truncated) + `attendance_date_for` (IST, overnight-aware). |
| 13 | `punch_in` (L104-105) | **Check-then-insert** for the duplicate-day guard — same race as #5. | Two simultaneous punch-ins for one day → two rows, not one 201 + one 409. | Unique `(emp_code, date)` index + insert; catch `DuplicateKeyError` → 409. |
| 14 | `punch_in` (L119-121) | Adds an `id` field and returns `punch_in` as a datetime; the contract has **no id** and wants epoch ms. `status` is an unvalidated `str`, so `ABSENT`/garbage is accepted at punch-in. | Response has `id`, `punch_in` not an int; `status:"ABSENT"` creates a presence row. | `record_out` serializer; `PresenceStatus` enum → 422 on non-presence. |
| 15 | `list_attendance` (L144-150) | **Loads the whole collection into memory** (`list(find(q))`), sorts and slices in Python. On ~100k rows this is slow and memory-heavy — explicitly forbidden. | `GET /attendance` on the grader's dataset is slow; `/admin/explain` would show a COLLSCAN + in-memory sort. | DB-side `.sort(...).skip().limit()` on an index + `count_documents(q)`. |
| 16 | `list_attendance` (L145) | Sorts by `date` only; contract is `date` **desc, then `emp_code` asc**. Also `date_from > date_to` isn't rejected, and `status` isn't validated. | Rows with the same date come back in arbitrary order; `date_from=2026-02&date_to=2026-01` is accepted. | Compound sort; explicit 422 on reversed range; `Status` enum. |
| 17 | `list_attendance` (L149) | Leaks `_id` as `id`; returns datetimes, not epoch ms. | Response shape doesn't match `AttendanceRecord`. | `record_out`; project `{_id:0}`. |
| 18 | `health` (L72-74) | Returns `{"status":"ok"}` **without pinging MongoDB**; it can never return 503 even when the DB is down, so the readiness probe lies. | Stop MongoDB, `GET /health` still 200; the runner starts testing against a dead DB. | `client.admin.command("ping")`; 503 on failure. |
| 19 | Global (L22-23) | `MongoClient(...)` without `tz_aware=True` → datetimes read back are **naive**, which then get mixed with aware datetimes elsewhere. | Subtracting stored `punch_in` from an aware instant raises `TypeError`. | `MongoClient(MONGO_URI, tz_aware=True)`. |
| 20 | Whole file | Missing endpoints: punch-out, PATCH regularize, all four analytics, and `/admin/explain`; no index creation at startup. | Most of the contract 404s; explain requirement unmet. | Implemented all, with `ensure_indexes()` at startup (idempotent). |

## Looked at, decided **not** a defect

- **`load_dotenv()` before reading env vars** — correct. `python-dotenv` does not override variables already present in the real environment, so real env vars still win (contract requirement). Kept it.
- **`EmployeeIn` default shift `09:30` / `18:30`** — matches the OpenAPI schema defaults. Kept (added pattern validation around them).
- **Returning `doc` directly after `pop("_id")` in create** — the *mechanism* (removing `_id`) is fine; only the serialization of `created_at` was wrong, which #7 fixes. Removing `_id` from responses is correct and retained.
- **Using `emp_code` (not `_id`) as the external identifier** — correct per the data model; no change.
